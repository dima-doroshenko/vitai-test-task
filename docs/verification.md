## API и данные

- 9 локальных тестов `node:test` прошли: BY fixed/mobile/VoIP, синтаксис и
  нормализация, обязательные поля, ограничения длины/тела, whitelist меток,
  невалидные запросы без записи, honeypot, environment mismatch.
- Окно 600 секунд: 599 запрещено, 600 разрешено; переход 1199 → 1200 не
  создаёт календарного обхода. Повтор не продлевает окно. Тестовые часы
  находятся только в in-memory SQLite; публичного управления временем нет.
- В реальной preview D1: 20 параллельных HTTPS POST дали 1×201 + 19×409;
  одна запись. После операторского изменения времени только этого fixture
  новая заявка допустима. Невалидные запросы не меняют число записей.
  Результат: `remote-check.json`, повторение: `scripts/check_remote.py`.
- Из браузера пройдены CTA → prefill → форма → 201 → повтор 409 в preview
  и production. Authenticated D1 запрос подтвердил один production fixture,
  нормализованный номер, интерес subscription, first/current attribution.
  Все пять UTM и три click ID сохранены, private query отброшен.
- Telegram подтвердил доставку первой явно помеченной тестовой заявки:
  D1 `sent`, `attempts=1`, ID и время в `production-check.json`.
- Проверены сбой D1 до записи, потеря D1 acknowledgment после commit,
  потеря ответа HTTP и последующий повтор. Уведомление из outbox не теряется
  после неоднозначного D1 результата.
- Timeout/ошибка Telegram после записи, 429/retry_after, lease при
  параллельной доставке, последующий успех, лимит попыток и длинное
  уведомление проверены локально с подменой только транспортного fetch.
  Production не отключалась для этих тестов.
- В production/preview разные D1 и Workers; preview Telegram disabled,
  секреты только production. Production API не доступен через workers.dev.

## Браузер и доступность

- Chrome/Playwright: 320×720, 375×812, 390×844, 768×1024, 1440×1000,
  844×390. После исправлений горизонтальной прокрутки нет.
- Дополнительно текст 200% на ширинах 320, 390, 768 и 1440; browser reflow
  при эквивалентной 200% zoom ширине 720 px. Зафиксированные переполнения
  заголовков/формы исправлены. Текст сохраняется, фиксированных перекрытий нет.
- Клавиатура: skip link, переход CTA по Enter, фокус на имени, Tab к телефону,
  видимый outline, native select, доступная кнопка. Мобильного modal menu нет.
- required и телефон связаны с inline errors через aria-describedby;
  aria-invalid, status/live region, disabled во время отправки. Проверены
  ошибки полей и серверная 422, состояния 503 и обрыв сети с сохранением ввода.
- `prefers-reduced-motion: reduce` отключает анимацию и smooth scrolling.
  Контент виден без JavaScript; форма disabled и есть noscript пояснение.
- axe-core WCAG 2 A/AA, 2.1 AA, 2.2 AA на всех шести размерах: 0 violations
  после исправления контраста номеров доставки.
- Скриншоты: `output/playwright/` (локальные, не публичная папка).
  Проверка реальной клавиатуры телефона и полноценная работа VoiceOver/

  Доставка уведомления боту и доступность OG не доказывают такое превью.

## Free и CPU

В панели аккаунта подтверждён Free — current plan, $0; 100 000 запросов/день,
10 мс CPU, 5 GB общей D1, 10 БД. До проекта D1 не было; созданы 2 небольшие
БД. Существующий посторонний Worker не менялся, платные услуги не включались.
Документация Cloudflare и её лимиты перечислены в implementation.md.

Python/FastAPI smoke подтвердил архитектуру функционально, но CPU 14–168 мс
не подходит заданному бюджету. Пользователь согласовал JS. JS preview:
27 запросов, CPU 0–5 мс, медиана 2 мс. Измерения в cpu-*.json.
Ранний production с немедленным Telegram имел единичный 14,623 мс пик по
GraphQL (поля cpuTimeP* в микросекундах), без execution errors.
Поэтому финальная версия отделяет доставку от HTTP: Cron по одной записи.
Финальная доставка и CPU фиксируются отдельно; небольшая выборка не
гарантирует соблюдение лимита для любого будущего трафика.

## Lighthouse

Первичный публичный mobile: 97 / 100 / 100 / 100.
Финальные три mobile замера и desktop, HTML/JSON, версия Chrome/Lighthouse,
UTC timestamp, throttling, источник и медиана — в output/lighthouse/summary.json.

используются как доказательство опубликованной версии.
